## Finding 1: Canva's Parameterization via Autofill API
- **Claim:** Canva's Connect API parameterizes templates through a system called "Autofill." Users tag elements in a "Brand Template" with unique names. The API can then create a new design by populating these tagged elements with new `text`, `image` (via asset_id), or `chart` data. Global style changes like swapping a full color palette or font family are not supported via the REST API.
- **Source URL:** https://www.canva.com/developers/docs/connect-api/autofill/
- **Source Date:** 2024
- **Source Tier:** PRIMARY
- **Numbers:** N/A
- **Confidence Note:** High. This is official developer documentation. The main limitation is that it's data-injection, not full stylistic control.

## Finding 2: Figma's Programmatic Parameterization via Plugin API
- **Claim:** Figma's parameterization is handled by its Plugin API. Developers can programmatically create and manage components with properties. The `addComponentProperty` method creates controllable variables of type `TEXT` (content), `BOOLEAN` (visibility), and `INSTANCE_SWAP` (nested component). The `combineAsVariants` method groups components into a set, whose properties (e.g., "size", "state") can be changed.
- **Source URL:** https://www.figma.com/developers/api/
- **Source Date:** 2024
- **Source Tier:** PRIMARY
- **Numbers:** A component set is recommended to have fewer than 1,000 variants to avoid performance issues. A file is limited to ~2GB of memory usage in-browser.
- **Confidence Note:** High. Based on official API documentation. The "maximum" number of variables is a soft limit based on performance, not a hard API cap.

## Finding 3: Adobe's Dual-Layer Parameterization (Express SDK vs. Firefly API)
- **Claim:** Adobe exposes two levels of control. The Adobe Express Embed SDK offers high-level parameters for UI integration, such as `promptText`, `canvasSize`, and `templateId`. The underlying Firefly Services API provides granular, generative control, exposing parameters like `prompt`, `negativePrompt`, `contentClass` ('photo' or 'art'), `style` (e.g. 'hyperrealistic'), `seed`, `numVariations`, and `photoSettings` (intensity, contrast, etc.).
- **Source URL:** https://developer.adobe.com/firefly-services/docs/guides/api/image_generation/
- **Source Date:** 2024
- **Source Tier:** PRIMARY
- **Numbers:** The Firefly API allows generating 1-4 variations per call.
- **Confidence Note:** High. Official developer documentation clearly distinguishes the two SDKs.

## Finding 4: Jasper's API Exposes Layer-Specific & AI-Driven Variables
- **Claim:** Jasper's API provides two methods for visual variation. The `image-template/render` endpoint allows for layer-specific overrides within a template, including `text.content`, `text.color`, `imageFile`, and `background.color`. The "Image Suite" API offers more abstract, AI-driven variations like "Replace Background" (with a prompt), "Uncrop," and "Upscale" (to a new `width` and `height`).
- **Source URL:** https://documentation.jasper.ai/creator-api/reference/render-image-from-template
- **Source Date:** 2024
- **Source Tier:** PRIMARY
- **Numbers:** Scale can be set from 0 to 4.
- **Confidence Note:** High. Based on official API reference.

## Finding 5: Copy.ai, Predis.ai, and Lately.ai Template Variables
- **Claim:** Enterprise platforms expose template selection and content overrides.

## Finding 6: The Design Token Standardization Stack
- **Claim:** Design token standards form a workflow:
    1.  **W3C Design Tokens Community Group (DTCG):** Defines the standard data model for tokens (e.g., using `$value` and `$type` fields in JSON). This ensures interoperability.
    2.  **Tokens Studio (formerly Figma Tokens):** A tool (often a Figma plugin) used to *create and manage* design tokens, which can be exported in the W3C format.
    3.  **Style Dictionary:** A build tool that *consumes* the standardized token JSON and *transforms* it into platform-specific code (e.g., CSS variables, Swift code, Android XML).
- **Source URL:** https://www.w3.org/community/design-tokens/
- **Source Date:** 2023 (W3C Spec First Public Working Draft)
- **Source Tier:** PRIMARY
- **Numbers:** N/A
- **Confidence Note:** High. This relationship is well-documented by all three entities.

## Finding 7: Programmatic Design Tools Use JSON & HTML/CSS as Variables
- **Claim:** Programmatic design tools treat the entire design as a mutable object or document.
    - **Polotno.js:** Represents the entire canvas as a JSON object. Every property of every element (`x`, `y`, `text`, `fontSize`, `fill`, `opacity`, etc.) is a controllable variable within this JSON structure.
    - **HTML-to-Image (Puppeteer/Playwright):** These tools render an HTML page in a headless browser and take a screenshot. The "variables" are every possible HTML attribute and CSS property that can be changed on the page before capture.
    - **SVG Templating (Satori):** Vercel's Satori library allows developers to write JSX (HTML/CSS) which it converts to an SVG. Variables are the dynamic parts of the JSX, such as text content, image sources, or conditional styles.
- **Source URL:** https://polotno.com/docs/store-overview (Polotno), https://playwright.dev/docs/screenshots (Playwright), https://github.com/vercel/satori (Satori)
- **Source Date:** 2024
- **Source Tier:** PRIMARY
- **Numbers:** Essentially unlimited variables, constrained only by browser/server performance.
- **Confidence Note:** High. This is the fundamental architecture of these tools.

## Finding 8: Maximum Controllable Variables (Inferred)
- **Claim:** The maximum number of controllable variables varies significantly by system type.
    - **Template-based (Canva):** Strictly limited to the number of elements tagged in the UI, with a hard cap of **300-500 elements** per design.
    - **Component-based (Figma):** A soft limit. A component can have many properties (`BOOLEAN`, `TEXT`, etc.) and variant dimensions. A set of 10 variant properties with 2-3 options each can easily create thousands of permutations, but performance degrades after ~1,000 visible variants. The practical limit is likely **~10-20 explicit properties** per component.
    - **Generative AI (Adobe Firefly):** The API exposes a finite set of high-impact variables per call, around **10-15 parameters** (prompt, negative prompt, seed, style references, photo settings, etc.).
    - **Programmatic (Polotno, HTML-to-Image):** Effectively **unlimited**. Every single attribute of every element (position, color, font size, stroke, etc.) is a potential variable, leading to thousands or millions of controllable data points, limited only by rendering performance.
- **Source URL:** Synthesis of all previous findings.
- **Source Date:** 2026-03-15
- **Source Tier:** SECONDARY (This is a derived conclusion)
- **Numbers:** See Claim.
- **Confidence Note:** Medium-High. The numbers are inferred from documentation on limits and API structures, not from a single "maximum variables" declaration. The categories (Template, Component, Generative, Programmatic) provide a clear framework for understanding these different ceilings.
