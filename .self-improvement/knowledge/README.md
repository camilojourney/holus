## File Descriptions

- **growth-engine-vision.md** — North star document. Defines what Holus must become: a social media growth engine that analyzes competitors, extracts viral frameworks, and creates content using proven patterns. Read first.
- **voice-profile.md** — Camilo's writing voice extracted from 15 real published posts. Covers tone, sentence patterns, vocabulary, and platform-specific adaptations. Used by the marketing agent during content generation.
- **content-frameworks.md** — 7 structured content frameworks (Breakdown, Contrarian, Before/After, Thread, BTS, Engagement Bait, Data Drop) with hook templates, platform rules, and voice notes. Machine-readable for the marketing agent.
- **platforms.md** — Platform profiles (LinkedIn, Twitter, Instagram, TikTok, YouTube Shorts) with API details, audience data, character limits, and best practices.
- **audience-profiles.md** — Target audience profiles for Pilaster, genpeli, and invoz. Demographics, pain points, content preferences, and platform habits.
- **content-formats.md** — Content type taxonomy ranked by expected engagement and effort. Templates for each format.
- **content-marketing-strategy.md** — Research agenda for content marketing trends. Preliminary — needs validation from real analytics.
- **viral-frameworks.md** — 12 reverse-engineered viral post patterns from the AI consulting/builder niche on LinkedIn. Machine-readable format with hook patterns, structures, real examples, and consulting angles. Used by the marketing agent during REASON stage for framework selection.
- **performance-patterns.md** — Auto-generated by the weekly learning loop (`just learn`). Currently empty — will populate when analytics data is available.
- **cross-repo-changes.md** — Factual log of every change the builder agent makes in sibling repos (social-media-automatization, genpeli, pilaster).

## Structure

- `current/` — Active knowledge files used by agents
- `archive/` — Superseded versions, rotated automatically via `archive_knowledge()` utility
- `requests/` — Knowledge gap requests filed by any agent, processed by experts

## How It Works

1. Expert agents update topic files on their research cadence
2. Each update archives the previous version to `archive/`
3. Confidence levels reflect data quality (none → preliminary → medium → high)
4. The marketing agent reads these files during OBSERVE and REASON stages
5. The weekly learning loop auto-updates `performance-patterns.md`

## Scope

**In scope:** market intelligence, content strategy, platform data, audience research, voice/tone, content frameworks, performance analytics.

**Out of scope:** architecture docs (`ARCHITECTURE.md`), code patterns, implementation details, trading systems.
