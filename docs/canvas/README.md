design canvases, not live dashboards.

| Layer | Where | Question |
| --- | --- | --- |

| Control | CLI commands, queue tools, prompt/config edits | What can I change safely? |

## How these stay durable

- Source of truth is this git folder. Cursor sees them through a symlink:
  `~/.cursor/projects/Users-mini-openclaw-workspace-github-holus/canvases -> docs/canvas`.
- The directory is flat, with one `.canvas.tsx` per block.
- Canvases do not fetch live data. Numbers and statuses are dated snapshots.
- Re-link with:
  `bash /Users/mini/.openclaw/workspace/github/~fleet-system/system/skills/systems-canvas/scripts/link-canvas.sh holus`

## Refresh

- Full regen: `/systems-canvas holus`
- One block: `/systems-canvas holus --block <id>`
- Canvas audit: `/systems-canvas holus --audit`
- Dashboard audit: `/systems-canvas holus --audit-dashboards`

Every block ends with the live dashboard surface that should validate it. Because
Holus is not yet present in the systems-canvas dashboard registry, block 09 lists
the missing surfaces instead of pretending live wiring exists.
