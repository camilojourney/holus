**Requested by:** Juan Martinez
**Scope:** Full codebase map — what works, what's broken, what's disconnected, what should be deleted

## The Core Problem

Holus has been built in multiple passes by multiple agents without a clear "stop, does this actually run?" checkpoint. The result: a large, mostly working codebase where the critical path (idea → post → publish) has never run end-to-end.

## The One True Pipeline (what should exist)

```
Juan types idea (text / voice note / URL)
    ↓
POST /api/holus/ingest  [ingest.py — keep]
    ↓
voice_pipeline.run()   [voice_pipeline.py — keep, integrate into idea_runner]
    ↓
visual_pipeline OR card_generator (pick ONE visual approach)
    ↓
judge.evaluate() × 3  [written-content + brand-safety + engagement]
    ↓
Telegram approval message (post text + 2 image variants + buttons)
    ↓
Juan approves
    ↓
social-media-automatization publishes
    ↓
48h: performance_loop reads engagement → updates bandit weights
```

## What's Missing (not built at all)

1. **Worker that connects ingest → voice_pipeline → judge → Telegram** — the glue is missing

4. **LinkedIn knowledge loaded into prompts** — `.self-improvement/knowledge/current/platforms.md` has LinkedIn insights but isn't injected into content generation

## Bottom Line

The codebase is not a mess — it's 80% built. The missing piece is **the glue layer**: a single worker that reads from the queue, runs the full judge panel, sends the Telegram approval, waits for response, and publishes.

Everything else exists. The pipes just aren't connected.

**Do not build anything new until the existing pipeline runs end-to-end once.**
